# 中価格帯LLM+無料Workerで授業1回3千円に収める

**結論: Tinkerable Sketch のコードベース視覚生成は、「GitHub Pages → Cloudflare Workers(無料枠)→ 構造化出力対応の中価格帯モデル」という構成で組み、幾何の保証はブラウザ側の検証・修復・決定的ジェネレータに任せるのが最適で、費用は授業1回(40人×30回=1,200リクエスト)あたり Claude Sonnet 5 で約1,800〜2,600円、GPT-6 Luna や Gemini 2.5 Flash-Lite なら約120〜130円、研究(60人×50回=3,000リクエスト)でも最大級の Sonnet 5 で4,500〜6,600円に収まる。** 第一候補は Claude Sonnet 5(入力$2/出力$10、構造化出力GA、Startティアで1,000 RPM)で、同価格・同格の代替が GPT-6 Sol、低価格側の代替が GPT-6 Luna($0.10/$0.50)と Gemini 2.5 Flash-Lite($0.10/$0.40)である。中国系モデルは DeepSeek V4-Flash を DeepInfra 等の米国ホスト経由で使えば1回0.06円と最安かつゼロ保持だが、本家API(中国本土保存・学習利用)や Gemini 無料枠(製品改善に利用・人間レビューあり)は倫理審査上避けるべきである。金額はどの選択肢でも研究費の消耗品レベルであり、実務上の論点は「モデルの単価」ではなく「スキーマ設計と幾何検証の分業」「レート制限ティア」「データ保持の説明可能性」「Gemini 3.x のプロモ価格終了(2027年1月に倍額)」にある。先行研究(LayoutGPT/LayoutPrompter/CreatiPoster)と産業側(json-render/A2UI/Figma First Draft)は「閉じたカタログ+数値パラメータをJSONで出力させ、クライアントが描画する」方式に収斂しており、Tinkerable Sketch のグリッド+ブロック+表現パラメータという方針はこの潮流に正確に一致する。

## 「LLMは意味判断、ブラウザは幾何保証」に分業する仕様が品質と費用を同時に決める

学術側の主流は2023年の LayoutGPT / LayoutPrompter 以来、レイアウトをCSS/HTML風あるいはJSONのコード風テキストとしてLLMに出力させる方式で、LayoutPrompter は **1入力あたり10候補を temperature 0.7 で生成し、Alignment・Overlap・mIoU を重み付けしたランカーで選ぶ**ことで学習ベース手法と同等以上の品質を訓練なしで達成した([arXiv 2311.06495](https://arxiv.org/html/2311.06495))。2025〜26年は LayoutCoT(RAG+3段階CoT)、LaySPA(RLで空間推論を強化)、CreatiPoster(レイヤー単位のJSON仕様を出力)へ発展しているが、Design2Code の失敗分析が「正しいレイアウト設計の生成」を主要な失敗要因と特定し([arXiv 2403.03163](https://arxiv.org/abs/2403.03163))、LaySPA 論文もLLMの空間推論の弱さを出発点にしている([arXiv 2509.16891](https://arxiv.org/abs/2509.16891))ことから、**幾何をLLMに任せきりにせず、ローカルで検証・修復する設計が必須**である。産業側も同じ結論で、Vercel json-render は開発者定義のコンポーネントカタログとZodスキーマの範囲内でしかLLMに出力させず([GitHub vercel-labs/json-render](https://github.com/vercel-labs/json-render))、Google A2UI は実行コードではなく宣言的JSONを渡して信頼済みカタログで描画する([Google Developers Blog](https://developers.googleblog.com/introducing-a2ui-an-open-project-for-agent-driven-interfaces/))。Tinkerable Sketch は既にブロック型(heading/body/image/shape)が固定されているため、この「制約付きカタログからの選択+パラメータ充填」方式に最適である。

スキーマ設計で決定的に重要なのは、**Anthropic と OpenAI の構造化出力が `minimum`/`maximum`/`maxItems`/`pattern` をサポートしない**点である([Claude Platform Docs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)、[OpenAI docs](https://developers.openai.com/api/docs/guides/structured-outputs))。Gemini の `responseSchema` は `minimum`/`maximum`/`minItems`/`maxItems` に対応するが、公式自身が「構文的に正しいJSONでも、値は必ずアプリ側で検証せよ」と明記している([Gemini API docs](https://ai.google.dev/gemini-api/docs/structured-output))。したがって座標・サイズは **整数セルの `enum`(x: 0..11、w: 1..12 など)で表現し、制約デコーディングの段階で範囲外を排除**し、`x+w ≤ cols` のような関係制約と重なりはクライアントで決定的に修復する。表現パラメータ(タイプスケール、ウェイト、余白、装飾)もすべて有限の enum にすれば、CSSカスタムプロパティへ1対1でマッピングでき、スキーマ違反もゼロになる。The Structured Output Benchmark は「JSON合格率がほぼ100%でも値の正確性は15〜25ポイント低い」ことを示しており、Value Accuracy は Qwen3.5-35B 0.801 > GPT-5.4 0.798 > Gemini 2.5 Flash 0.796 > Claude Sonnet 4.6 0.779 と、モデル間差よりも「合格率と値の正確性の差」のほうが大きい([arXiv 2604.25359](https://arxiv.org/pdf/2604.25359))。つまり検証層の有無が、モデル選定より品質を左右する。

クライアント側パイプラインは、スキーマ検証(zod)→クランプ→ロック済みブロックの原値上書き→固定順序での衝突解消(下方押し出し)→LayoutPrompter式の局所スコア(左端揃え本数・空セル率・余白バランス)による候補のランキングと重複除去→全滅時は seed 付きPRNGの決定的ジェネレータで補完、という順に組む。この **決定的ジェネレータは、LLM障害時のフォールバック、研究の統制条件、オフライン授業の3役**を担うので、API接続より先に実装する価値がある。さらに「LLMは文法名・比率・階層といった意味的パラメータだけを選び、座標はジェネレータが決める」ハイブリッドにすると、出力トークンは数十に圧縮され幾何違反はゼロになる。LayoutNUWA が固定部分をHTMLに書き未定部分をマスクで穴埋めさせたように([arXiv 2309.09506](https://arxiv.org/pdf/2309.09506v2))、ロック済みブロックは出力スキーマから除外して「変更禁止」を構造的に表現するのがトークン節約と違反ゼロの両面で有利である。候補数は「1コールでN案」を基本にし(入力プロンプトを1回しか払わないため入力コストが約1/N)、多様性不足なら「前案と異なる構成にせよ」の明示か2コール×2案へ切り替える。多サンプル推論では候補プールの多様性が正解包含率を上げる一方、温度上昇は品質を落とすため([arXiv 2502.05234](https://arxiv.org/html/2502.05234v2))、この「batch vs incremental」「1コールN案 vs Nコール」は研究の独立変数としても設計できる。

## 第一候補は Sonnet 5、低価格代替は GPT-6 Luna と 2.5 Flash-Lite、本家中国APIと無料枠は回避

本用途は「見出しは本文より大きく」「余白は3段階から」「ロックされたブロックは動かさない」といった複数ルールを同時に守る判断であり、第三者評価は「Sonnet は複数のルールや判断を追跡するタスクで指示追従がより正確」「Haiku は速度・コストがボトルネックの構造化抽出に向く」としている([emergent.sh](https://emergent.sh/learn/claude-sonnet-vs-haiku))。**Claude Sonnet 5 を第一候補**とする根拠は、(1) 入力$2/出力$10 が導入価格から恒久価格に変更済みで、9月1日に予定されていた$3/$15への値上げが撤回されたこと、(2) 構造化出力と strict tool use が全現行モデルでGA・ベータヘッダ不要で、文法制約サンプリングによりスキーマ準拠が保証されること、(3) Start ティアの公式レート制限が **1,000 RPM・2M ITPM・400K OTPM** と授業のピーク(40人が10秒に1回=240 RPM、720K ITPM)を余裕で吸収し、しかもキャッシュ読出は ITPM に算入されないこと、(4) `output_config.effort: "low"` で思考トークンを抑えられ、Batch API で研究の事後一括生成が半額になること、(5) 商用データは学習に使われず30日以内に削除され、日本国内処理が審査要件になっても Amazon Bedrock 東京リージョン(+10%)という逃げ道があること、である([Anthropic Pricing](https://platform.claude.com/docs/en/about-claude/pricing)、[Structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)、[Rate limits](https://platform.claude.com/docs/en/api/rate-limits)、[API and data retention](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention))。留意点は、Haiku 4.5 は最小キャッシュ長が4,096トークンで想定2,500トークンの system prompt ではキャッシュが効かず、`claude-haiku-4-5-20251001` は2026年10月15日以降いつでも廃止告知され得ること、Sonnet 5 は最小1,024トークンでキャッシュが効き −32%になること、Sonnet 5.5 / Haiku 5.5 が「数週間以内」と予告されていることで、**モデルIDと effort とスキーマは設定ファイル化**して即切替できるようにする([Prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)、[Model deprecations](https://platform.claude.com/docs/en/about-claude/model-deprecations)、[Anthropic news](https://www.anthropic.com/news/claude-opus-5-5))。

**同格の代替は GPT-6 Sol**(2026-09-22発表、$2/$10、GPT-5.6比で半額かつ恒久価格と明言)で、日本語品質は Nejumi Leaderboard 4 で gpt-5.6-sol が0.8499(6位)と Sonnet 4.6 の0.8230(24位)を上回る([OpenAI: Introducing GPT-6 Sol and Luna](https://openai.com/index/introducing-gpt-6-sol-and-luna/)、[Qualiteg Nejumi 4](https://journal.qualiteg.com/llm-ranking-2026/))。Sonnet 5 と GPT-6 Sol は価格・機能で実質同格であり、決め手はレート制限の公式明示、Batch とキャッシュの文書化、東京リージョンの有無という運用面である。発表翌日の GPT-6 は実運用データが乏しく、OpenAI 各ティアのモデル別 RPM/TPM 公式値も未取得なので、採用するなら授業前に Tier 1 の実値をヘッダで確認する。**低価格側の代替は GPT-6 Luna($0.10/$0.50、¥132/授業)と Gemini 2.5 Flash-Lite($0.10/$0.40、¥116/授業)**で、レイアウト数値と enum の決定には足りる一方、日本語文章の質は一段落ちる(gpt-5.6-luna は Nejumi 33位 0.8145)。これらは「編集ごとの自動生成(incremental)」条件のように呼び出し回数がボタン方式の5〜10倍に膨らむ場面や、ウォームアップ、フォールバックに割り当てるのが合理的である。Gemini は 3.6 Flash が Flash 級で Nejumi 15位(0.8312)と日本語に強く、スキーマで `minimum`/`maximum` が使え、キャッシュも $0.075 と安いが、**3.x Flash の$0.75/$3.75 は2026年12月31日までのプロモ価格で2027年1月1日から$1.50/$7.50に倍額**となり、3.6→3.7→3.8 Flash が6週間で3世代更新される速さ、Tier 1 の日次上限1,000 RPD(第三者値)が授業1回の1,200リクエストを超え得る点、処理リージョンを指定できない点が計画リスクになる([Google Blog: Gemini 3.8 Flash](https://blog.google/innovation-and-ai/models-and-research/gemini-models/3-8-flash-and-3-8-flash-cyber/)、[AI Free API: Gemini free tier limits](https://www.aifreeapi.com/en/posts/gemini-api-free-tier-rate-limits))。

中国系オープンウェイトモデルは、**本家APIを避けて米国ホスト経由で使う**のが唯一の現実解である。DeepSeek V4-Flash は DeepInfra で$0.09/$0.18 と本家ピーク価格($0.30/$1.20)より安く、しかも本家のオフピーク割引(UTC 01:00–04:00 / 06:00–10:00 以外)は日本の平日昼の授業時間帯にほぼ効かない([DeepSeek Pricing](https://api-docs.deepseek.com/quick_start/pricing)、[DeepInfra Pricing](https://deepinfra.com/pricing))。Fireworks はオープンモデルについてオプトインなしにプロンプト/生成をログ・保存せず学習にも使わない Zero Data Retention を明記し([Fireworks Data Security](https://docs.fireworks.ai/guides/security_compliance/data_security))、Hugging Face Inference Providers はプロバイダ価格をマークアップなしで転嫁する請求統合窓口として使える([HF Inference Providers Pricing](https://huggingface.co/docs/inference-providers/en/pricing))。日本語品質も Qwen3.8-2.4T が Nejumi 0.8598 でオープンモデル初の0.85超え、GLM-5.3-Flash 0.8260、DeepSeek-V4-Flash 0.8169 と高水準だが([Qualiteg](https://journal.qualiteg.com/llm-ranking-2026/))、Alibaba 公式のシンガポール(国際)リージョンは JSON Schema モード未対応で画像入力時はスキーマ制約が無効になり([Alibaba: Qwen structured output](https://www.alibabacloud.com/help/en/model-studio/qwen-structured-output))、Kimi・Z.ai の厳密スキーマ対応は一次情報で未確認である。したがって中国系は「研究の比較条件」または「最安フォールバック」として DeepSeek V4-Flash か Qwen3.5-35B-A3B を DeepInfra/Together 経由(Together は structured outputs を公式提供 [Together docs](https://docs.together.ai/docs/inference/chat/structured-outputs))で使うにとどめ、本命にはしない。

回避すべき選択肢を整理すると、Fable 5.1 / Opus 系(JSON生成にはオーバースペックで出力単価が Sonnet 5 の2〜5倍)、Gemini 無料枠(後述の通りデータが製品改善に使われる)、DeepSeek・Kimi・Z.ai・MiniMax の本家API直接利用と Alibaba 北京リージョン(中国本土ホスト)、GPT-5-nano(最安だが旧世代で非推奨扱い)、o-series(推論過剰)、Haiku 4.5 へのハードコード、セルフホストGPU、本番授業でのブラウザ内モデル、ラスター画像生成、そしてAPIキーのフロントエンド埋め込みである。

## バックエンドは Cloudflare Workers 無料枠で0円、ただしKV書き込み上限に注意

GitHub Pages は静的配信のみなので、APIキーを隠しレート制限と支出上限をかける薄いバックエンドが必須である。**Cloudflare Workers Free(1日10万リクエスト、CPU 10ms/呼び出し、$0)が最有力**で、LLM呼び出しはI/O待ちが支配的でCPUを消費しないため10msでも十分であり、同一アカウントで KV、Rate Limiting binding、無料の AI Gateway(キャッシュ・レート制限・分析・日/週/月の支出上限で自動停止)が揃う([Cloudflare Workers Pricing](https://developers.cloudflare.com/workers/platform/pricing/)、[AI Gateway Pricing](https://developers.cloudflare.com/ai-gateway/reference/pricing/))。次点は Deno Deploy Free(100万req/月、CPU 10時間/月)、Vercel Hobby(最大300秒、ただし非商用条項)、Supabase Edge Functions(無料DBと同居できるが7日無活動でプロジェクト一時停止)で、**Netlify Free は300クレジット/月の硬い上限で枯渇時にチーム内の全サイトが停止するため不向き**である([Deno Deploy Pricing](https://deno.com/deploy/pricing)、[Vercel Functions Limits](https://vercel.com/docs/functions/limitations)、[Supabase project pausing](https://supabase.com/docs/guides/platform/free-project-pausing)、[Netlify Docs: credits](https://docs.netlify.com/manage/accounts-and-billing/billing/billing-for-credit-based-plans/how-credits-work/))。

推奨構成は「GitHub Pages → Worker `/api/generate` → AI Gateway → LLM API」で、鍵は Worker の Secret に置き、CORS は GitHub Pages ドメインと localhost に限定する。認証は授業ごとにローテーションする共有クラスルームコード(`X-Class-Code` ヘッダを Secret と照合、学生は授業で入力して localStorage に保存)で十分で、漏洩時は Secret 更新だけで無効化できる。ユーザ単位の制限は端末生成UUIDをキーに Rate Limiting binding(10秒または60秒窓)で短期バーストを抑え、日次上限は永続カウンタで管理するが、ここに落とし穴がある。**KV の書き込みは1日1,000回が上限**で、1回の生成につき1書き込みでも授業1回1,200リクエストは超過するため、日次カウンタは Durable Objects(10万req/日無料)か D1(書き10万行/日)に置く必要がある([Cloudflare Workers Pricing](https://developers.cloudflare.com/workers/platform/pricing/)、[Rate Limiting docs](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/))。支出上限は AI Gateway/プロバイダ側のハードストップと、Worker 側の日次トークン集計による `503 {reason:"budget"}` の二重にする。Worker は CPU 10ms 制約のため認証・レート制限・転送・usage ログに徹し、スキーマ検証と修復はブラウザで行う。正規化した入力(グリッド状態+意図+プロンプトバージョン)のSHA-256をキャッシュキーにすると、同じ課題を同じ初期状態から始める授業ではヒット率が期待できる一方、研究では「同じ入力に同じ出力」が条件間比較を歪めないよう、キャッシュヒットもイベントとして記録し、「もう一度生成」は nonce でバイパスする。

レイテンシは小型モデルで TTFT 0.35〜0.6秒、出力100〜200 tok/s が目安で、Gemini 2.5 Flash ≈450ms/204 tok/s、Claude Haiku 4.5 ≈597ms、Claude Sonnet 4 ≈900ms/53 tok/s という実測がある([kunalganglani.com](https://www.kunalganglani.com/blog/llm-api-latency-benchmarks-2026))。3案×10ブロック≒600〜1,000トークンのJSONなら総時間3〜8秒で、非ストリーミング+スケルトンUIから始めて後で Vercel AI SDK の `partialObjectStream` 相当の「案単位の漸進表示」へ移行するのが低リスクである([aihero.dev](https://www.aihero.dev/streaming-objects-with-vercel-ai-sdk))。Anthropic の構造化出力は初回リクエストで文法コンパイルの遅延が乗り24時間キャッシュされるので、**授業開始前にウォームアップ呼び出しを1回入れる**と初学者の初回体験が安定する。呼び出しは明示ボタン+クールダウン(5秒程度)+日次上限(30回/人程度)を基本とし、編集ごとの自動生成は800ms以上のデバウンスと `AbortController` による中断を付けた研究条件としてのみ有効化する(Worker はクライアント切断を検知できるとは限らず上流トークンは消費されるため、その分もログに残す)。

## 倫理審査は「匿名ID・本文ハッシュ化・画像非送信・有料ティア」の4点で通す

送信内容をレイアウトパラメータと短い意図テキストに限定し、**氏名・学籍番号はアプリ側で端末生成UUIDに置換し、ブロック本文は文字数と SHA-256 先頭8文字に置換、参照画像はブラウザで抽出した色統計だけを送る**設計にすれば、API 側の個人情報リスクは最小化され、審査書類も書きやすい。プロバイダ別の説明材料は次の通りである。Anthropic は商用利用規約で「Anthropic may not train models on Customer Content from Services」と明記し、入出力は受領から30日以内に自動削除、推論地域は既定 `global`(`inference_geo: "us"` で米国限定・1.1倍課金)、ZDR は営業経由の個別契約で CORS 非対応となるため小規模研究には過剰であり、標準の30日保持で十分である([Commercial Terms](https://www.anthropic.com/legal/commercial-terms)、[privacy.claude.com](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-personal-data)、[Data residency](https://platform.claude.com/docs/en/manage-claude/data-residency))。OpenAI API は既定で学習利用なし、濫用監視ログは最長30日、日本リージョン(jp.api.openai.com)は保存のみで処理は米国、2026年3月5日以降のモデルは10%割増である([OpenAI: Data controls](https://developers.openai.com/api/docs/guides/your-data))。**Gemini は無料枠では「Google uses the content you submit … to provide, improve, and develop Google products」「Human reviewers may read, annotate, and process your API input and output」と規約に明記されており、研究参加者データを扱う本件では必ず課金アカウント連携の Paid で運用**しなければならない([Gemini API Additional Terms](https://ai.google.dev/gemini-api/terms))。処理まで国内に留める要件が出た場合は Vertex AI の asia-northeast1(東京)が「ML processing … occurs within the specific region」を保証するが、3.x モデルの東京提供は未確認である([Vertex AI Data residency](https://cloud.google.com/vertex-ai/generative-ai/docs/learn/data-residency))。

中国系の本家APIは審査上の説明が困難である。DeepSeek のプライバシーポリシー(2026-02-10発効)は収集情報を中華人民共和国内のサーバに保存し、モデル訓練・技術改善に利用する(オプトアウト権あり)と明記し([DeepSeek Privacy Policy](https://cdn.deepseek.com/policies/en-US/deepseek-privacy-policy.html))、デジタル庁は2025年2月6日に「DeepSeek等の生成AIの業務利用に関する注意喚起」を発出、広島大学CSIRT など国内大学がこれを周知している(禁止ではなく注意喚起)([デジタル庁 PDF](https://www.digital.go.jp/assets/contents/node/basic_page/field_ref_resources/d2a5bbd2-ae8f-450c-adaa-33979181d26a/e7bfeba7/20250206_councils_social-promotion-executive_outline_01.pdf)、[広島大学CSIRT](https://csirt.hiroshima-u.ac.jp/2025/deepseek-%E7%AD%89%E3%81%AE%E7%94%9F%E6%88%90ai%E3%81%AB%E9%96%A2%E3%81%99%E3%82%8B%E6%B3%A8%E6%84%8F%E5%96%9A%E8%B5%B7/))。学生が入力する自由文や画像に個人情報が混入し得る以上、中国本土サーバへ送る設計は避け、使うなら米国ホストのゼロ保持条件を研究計画書に引用する。埼玉工業大学の学内ガイドラインにおける中国系API の明示規制の有無は本調査の範囲外なので、申請前に確認が必要である。

研究ログは Supabase(匿名サインイン+RLS で自分の participant_id 行の INSERT のみ許可)か Firestore(無料枠 読み5万/日・書き2万/日)に置き、Cloudflare AI Gateway のログ(Free で全ゲートウェイ合計10万件)は運用監視用に限定する([Supabase Anonymous Sign-Ins](https://supabase.com/docs/guides/auth/auth-anonymous)、[Firestore quotas](https://firebase.google.com/docs/firestore/quotas))。Firestore は40人×500イベントで1日2万書き込みの上限に達するためイベントのバッチ化が要り、Supabase は授業のない週に一時停止するため週1回の cron ping(Cloudflare Cron Triggers は無料)で活性維持する。イベントには `gen_request`(正規化入力ハッシュ・ブロック構成・意図・プロンプトバージョン・モデル)、`gen_response`(レイテンシ・usage・キャッシュヒット・**修復前の生JSON**・局所スコア・修復ログ)、`variant_accept/reject`、`manual_edit`、`param_change` を含め、条件(batch/incremental/deterministic)を授業回コードに紐付ける。修復前の生JSONを保存することで、構造化出力の失敗・修復頻度そのものが研究データになり、受容率・採択までの時間・採択後の編集量・局所品質スコアと採択の相関・条件別の総トークンと総待ち時間がすべて事後に再構成できる。同意は授業内で紙またはLMSで取り、participant_id とは紐付けない。

実装は次の順序で進めると、API契約前にアプリの骨格が完成し、モデルは最後に差し替え可能な部品になる。第1段階は API なしで、レイアウト/スタイルの JSON スキーマ(整数セルの enum、表現パラメータの enum)、zod 検証、クランプ・衝突解消・スコアリングの修復パイプライン、seed 付き決定的ジェネレータ、複数案の提示と採択UIを Vite+React 内に実装し、教員作成のお手本レイアウトを few-shot exemplar として2〜5件用意する。第2段階で Cloudflare Worker を `/api/generate` として立て、Secret にキー、`X-Class-Code` 照合、Rate Limiting binding、Durable Objects/D1 の日次カウンタ、AI Gateway の支出上限とキャッシュ、CORS 限定を設定する。第3段階でプロバイダアダプタを書き、Claude は `output_config.format` + `effort: "low"` + system prompt の `cache_control`、OpenAI は strict Structured Outputs、Gemini は `responseSchema` に対応させ、モデルID・effort・スキーマ・プロンプトバージョンを設定ファイル化する。第4段階でロギングを Supabase/Firestore に接続し、Worker 側からも usage とレイテンシをサービスロールで二重記録する。第5段階でパイロットを行い、`/v1/messages/count_tokens`(無料)で実プロンプトのトークン数を計測し、クレジットを購入して数百リクエストの履歴を作ったうえで Console の Limits ページで Evaluation ティアの実値を確認し、授業直前のウォームアップ呼び出しを運用手順に組み込む。第6段階として研究では、保存した入力に対する複数モデル・複数試行の事後一括生成を Batch API(半額)+1時間キャッシュで行い、Opus 5.5 や GPT-6 Sol、DeepSeek V4-Flash を比較条件に加える。

## Conclusion

この調査で最も重要な知見は、費用の問題がほぼ消滅し、設計の問題だけが残ったことである。授業1回の LLM 費用が最安120円から最大でも5千円という規模では、モデルの単価差よりも「スキーマで座標を enum 化し幾何をブラウザで保証する」「決定的ジェネレータを先に作る」「KV の書き込み上限やレート制限ティアを授業規模に合わせる」「Gemini を無料枠で使わない」といった判断のほうが、品質・安定性・審査通過のすべてに効く。同時に、コード生成がラスター生成の30〜100分の1の費用と10分の1以下の待ち時間で無数の試行を許すという事実は、Tinkerable Sketch が主張する「いじりやすさ」の物質的基盤であり、研究の主張そのものを費用データで支えられる。

今後の含意として、モデルの世代交代が数週間単位(Gemini 3.x Flash が6週間で3世代、Sonnet 5.5 / Haiku 5.5 が予告済み、GPT-6 が発表翌日)で進む以上、特定モデルへの最適化は投資として割に合わない。プロバイダアダプタと設定ファイルで差し替え可能にし、修復前の生JSONを全件保存しておけば、モデルが変わっても同じ入力で再評価でき、「どのモデルがデザイン初学者の採択率を上げるか」という問い自体を研究の継続的な従属変数にできる。未検証事項として、Sonnet 5 / GPT-6 / Gemini Flash-Lite の日本語 Nejumi スコア、Cloudflare Rate Limiting binding の Free プラン可否、Vertex 東京での 3.x 提供、学内ガイドラインの中国系API規制は、パイロット前に一次情報で確認すべきである。
